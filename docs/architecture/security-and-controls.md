# Security and operating controls

Default development and test configuration must have fake publishing, `PUBLISHING_ENABLED=false`, dry-run on, manual approval on, and global automation off. A live call requires explicit production configuration plus passing gates at dispatch time: global enabled, account active, publishing enabled, mode, approval for the exact draft/asset version, valid asset and policy checks, daily/rate limits, duplicate check, credentials, and platform requirements. A gate failure records a decision and stops the call. An administrator can pause an account or all automation; the publishing disable switch is independent.

Access control must distinguish read, configuration, approval, and system-control actions. Record actor, target, old/new values, and time for administrative changes. Account credentials and provider secrets belong in environment-backed configuration initially, never in content records, prompts, logs, screenshots, Git, or `.env.example` values. Plan for secret-manager replacement without changing domain code. Rotate/revoke leaked credentials and invalidate affected sessions.

Phase 1 account routes require a server-side `ADMIN_API_TOKEN` bearer token. It is a temporary single-administrator boundary, not browser authentication; future dashboard code must not receive it. The authorization dependency can be replaced when user authentication is designed. Account writes create account-scoped change events. Health endpoints are public but reveal only status. Startup rejects missing token outside tests and rejects automation or publishing flags that would violate Phase 1 safe mode. No publishing code exists yet.

Treat trends, media inputs, web content, and AI outputs as untrusted. Validate schemas, reject prompt-injection attempts as instructions, constrain network/file access, and review rights and platform policy before publication. Avoid copyrighted-content scraping/reposting. Apply provider timeouts, quotas, bounded retries, cost budgets, and idempotency; never let a retry bypass approval or cause an unchecked duplicate post. An uncertain external result requires reconciliation before retry.

Retain concise audit facts, not private chain-of-thought. Define retention/deletion and privacy practices before production data collection. The [domain model](domain-model.md) defines content lifecycles; [observability](observability.md) defines audit fields; [environments](../operations/environments.md) describes configuration.
